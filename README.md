# HSF2 Pipelined Floating Point Multiplier (FPMUL-PIPE)

HSF2 is a pipelined parameterized ANY-precision floating point multiplier designed for high-performance computing applications. 
It can be configured to support various floating point formats by adjusting the parameters for exponent and mantissa widths.

This IP is pipelined to achieve high throughput, making it suitable for applications requiring fast floating point arithmetic operations.

## Features
- Fully pipelined architecture w/ II = 1
- Parameterized exponent and mantissa widths
- Parameterized rounding modes, supporting multiple IEEE 754 rounding modes, including:
    - Round to Nearest Even
    - Round towards Zero
    - Round towards Positive Infinity
    - Round towards Negative Infinity
- Exception compatible: NaN/Infinity input and output


## Getting Started
### FuseSoC and Cocotb Requirements
This IP organized with [FuseSoC](https://github.com/olofk/fusesoc), a package manager and build system for HDL code.
To build and simulate the IP core, you need to have following requirements installed:
- fusesoc
- numpy
- pytest
- cocotb

You can simply use `uv` or other Python virtual environment tools to create a new environment,
then install the requirements with pip:
```
pip install fusesoc numpy pytest cocotb
```
All required programs will be automatically fetched by install these packages.

### RTL Infrastructure Dependencies
This IP core depends on the [RTL Infrastructure Library](https://github.com/hasu-ic-club/hasunosora-hdl-infra) provided by Hasunosora IC Design Club. 

The git URL of the library is already registered in the FuseSoC configuration file `~/.fusesoc/config` of the repository. So if you have set up FuseSoC correctly, it can automatically fetch the library when building the IP core.

### Building and Simulating the IP Core
We provide the core file and makefile to build and simulate the IP core with `Cadence Xcelium` simulator.
If you are using other simulators, please refer the section [Using Other Simulators](#using-other-simulators).

The cocotb-based environment of Xcelium simulator is prepared in the Makefile. You can simply run the following command in the terminal to build and simulate the IP core:
```
make run
```

This command will build the IP core and run the cocotb testbench. The simulation results will be displayed in the terminal. And the built files are stored in the `build/` directory. 
We enable the waveform dump by default with the simulation script `ip/tb/script/xrun.tcl`. You can enter the `build/hasunosora_arith_hsf1_fpadd_pipe_0.1a1/sim-xcelium/` directory after the simulation, and type `indago` to open the waveform viewer.

*Note: Because of the flow API of FuseSoC/Edalize does not support `Xcelium` now. We write some 'Makefile replace/fix statements' in the top Makefile (you can open it and see them). These statements modify the Makefile generated by FuseSoC tool API (which not support `cocotb`) to add the cocotb support. It's a temporary workaround, and we are 
already working on contributing the cocotb support to the FuseSoC/Edalize project.*

### Using Other Simulators

If you want to use other simulators, you need to modify the `ip/hsf1_fpadd_pipe.core` file manually to add the simulator-specific settings for your simulator. Please refer to the [FuseSoC documentation](https://fusesoc.readthedocs.io/en/latest/) for more details on how to configure the core file for different simulators.

Also, due to the simulator script `ip/tb/script/xrun.tcl` is written for `Xcelium`, you may need to remove it from the core file and write your own simulator script according to your simulator's requirements.

If you encounter any issues or need further assistance, please feel free to open an issue in this repository.
If you write a simulator script for other simulators, we also welcome you to contribute it back to this repository via pull requests.

## Testing
We make some simple and basic tests in the cocotb-based testbench to verify the functionality of the IP core.
Here is the a brief description of the test cases:

| Test Case Name | Description |
|----------------|-------------|
| verySimpleTest | A very simple test which give some combinations of simple numbers to test basic functionality |
| randomBinaryTest | Two operands' binary are random, we do not care about the number is a valid floating-point number or not. This test will test the robust of the IP |
| randomFloatTest | Two operands are random valid floating-point numbers |
| specialValuesTest | Two operands are combination of special floating-point values (NaN, Infinity, Zero, etc.) to test the handling of exceptional cases |
